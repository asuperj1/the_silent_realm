1.2 Entity 定义
字段	类型	说明
id	uint64_t	全局唯一ID，高32位=类型Hash，低32位=自增序列
generation	uint32_t	代数计数器，防止悬垂引用（ID复用后 generation++）
isAlive	bool	存活标记，false时System跳过处理
1.3 Component 定义（POD结构体，纯数据）
1.3.1 ClueComponent（线索物品）
字段	类型	说明
clueId	uint32_t	线索唯一编号
clueType	enum	KeyClue(关键线索) / SideClue(支线线索) / FakeClue(虚假线索，米·戈伪造)
fragmentIndex	uint8_t	碎片序号（0-based）
totalFragments	uint8_t	完整线索所需碎片总数
truthScore	int8_t	真实度（-100~100），负值=假情报，正值=真情报
revealsLocation	uint32_t	揭示的车厢ID（0=不揭示）
revealsNPC	uint32_t	揭示的NPC ID（0=不揭示）
relatedEventId	uint32_t	关联剧情事件ID
isAutoIdentified	bool	获取后是否自动识别真伪（PER≥阈值时自动true）
1.3.2 ConsumableComponent（消耗物品）
字段	类型	说明
effectType	enum	HP_RESTORE / SAN_RESTORE / BUFF_TEMP / CURE_WOUND / PURGE_VOID / LIGHT_SOURCE / REPAIR
effectValue	int32_t	效果数值（HP恢复量/SAN恢复量/Buff增幅百分比）
durationRounds	uint16_t	持续回合数（0=瞬间生效）
cooldownSeconds	uint16_t	使用冷却（0=无冷却）
maxCarryPerSlot	uint8_t	每格最大堆叠数（1=不可堆叠，0=无限制）
useInCombat	bool	战斗中是否可使用
useOutOfCombat	bool	非战斗是否可使用
targetScope	enum	SELF_ONLY / SINGLE_ALLY / ALL_PARTY / SINGLE_ENEMY
consumptionSound	string_id	使用音效ID
consumptionVFX	string_id	使用特效ID
1.3.3 EquipmentComponent（装备物品）
字段	类型	说明
equipSlot	enum	WEAPON / ACCESSORY / ARMOR / LIGHT_SOURCE
attrBonuses	std::array<int32_t, 7>	7属性加成 [HP, SAN, STR, DEX, CON, PER, WIL]
skillGranted	string_id	授予的额外技能ID（空=无）
durability	uint16_t	当前耐久
maxDurability	uint16_t	最大耐久
durabilityLossPerUse	uint8_t	每次使用/受击的耐久损耗
repairable	bool	是否可修理
repairCost	uint16_t	修理消耗诡秘点数
twoHanded	bool	是否双手占用
specialEffect	string_id	特殊效果ID（如"灵火附魔""对亡灵+30%伤害"）
1.3.4 TagComponent（标签）
字段	类型	说明
tags	std::vector<string_id>	标签列表，用于：1.场景匹配引擎 2.LootSystem筛选 3.KP叙述生成时的AI prompt注入
sceneOrigin	string_id	来源场景tag（空=无特定来源）
loreCategory	enum	VOID(虚空系) / MORTAL(凡人系) / MYTHOS(神话系) / RUINS(遗迹系) / TRAIN(列车系)
1.3.5 WeightComponent（负重）
字段	类型	说明
weight	float	单件重量（kg）
encumbrancePenalty	int8_t	负重超限后的DEX惩罚（每超1kg=-1DEX）
1.4 System 定义（纯逻辑，无状态）
1.4.1 ItemFactory（工厂）
Text
职责：根据物品模板ID创建物品Entity，注册所需Component
输入：itemTemplateId（如 "clue_passport_001"）
流程：
  1. 查ItemTemplateRegistry获取模板
  2. EntityManager::CreateEntity()
  3. 根据模板 componentMask 逐项 AddComponent()
  4. 如果模板有 generatorFunc → 调用生成随机属性（如耐久度浮动±10%）
  5. 发送 Event::ItemCreated
输出：Entity&
模板注册表（策划配置数据）:
  ItemTemplateRegistry = {
    "clue_passport_001" → {
      name: "散落的乘客护照",
      componentMask: [Clue, Tag],
      Clue: { clueType: SideClue, truthScore: 80, fragmentIndex: 0, totalFragments: 3, ... },
      Tag: { tags: ["护照", "乘客", "废都799年", "3号车厢"], loreCategory: MORTAL }
    },
    "consumable_bandage_001" → {
      name: "列车急救包",
      componentMask: [Consumable, Tag, Weight],
      Consumable: { effectType: HP_RESTORE, effectValue: 20, maxCarryPerSlot: 3, ... },
      ...
    }
  }
1.4.2 InventorySystem（背包）
Text
职责：增删改查、堆叠合并、负重计算
核心方法：
  AddItem(Entity& item, uint8_t slotIndex) → bool
    1. 查是否有可堆叠的同类型物品（ConsumableComponent.maxCarryPerSlot>1）
    2. 有→合并堆叠 无→占用新格子
    3. 负重超限→发送 Event::InventoryFull，返回false
    4. 发送 Event::ItemAcquired
  RemoveItem(uint64_t entityId) → bool
  GetItemsByTag(const std::string& tag) → std::vector<Entity*>
  GetItemsByType(ComponentType type) → std::vector<Entity*>
  GetTotalWeight() → float
  MergeStack(uint64_t fromId, uint64_t toId) → bool
1.4.3 ItemQuerySystem（查询）
Text
职责：多条件组合筛选 + 索引加速
支持筛选条件：
  - byType: Clue / Consumable / Equipment
  - byTag: 任意tag字符串
  - byRarity: Common / Uncommon / Rare / Epic
  - byEffectType: HP_RESTORE / SAN_RESTORE / ...
  - bySceneOrigin: 按来源场景筛选
  - byTruthRange: [minTruth, maxTruth]（用于识别虚假线索）
实现要点：
  - 对 TagComponent.tags 建倒排索引（tag → EntityIdSet）
  - 对 ComponentType 建位图索引
  - 多条件用SetIntersection合并
1.4.4 ItemEquipSystem（装备）
Text
职责：装备/卸下/耐久消耗/属性加成计算
核心方法：
  Equip(uint64_t itemEntityId, uint64_t characterEntityId) → bool
    1. 检查 equipSlot 是否已被占用 → 占用则自动卸下旧装备
    2. 检查属性要求（如 STR≥60 的长剑）
    3. 应用 attrBonuses 到角色属性Component
    4. 应用 skillGranted（临时技能写入角色SkillComponent）
    5. 发送 Event::ItemEquipped
  Unequip(uint64_t characterEntityId, EquipSlot slot) → bool
  ApplyDurabilityLoss(uint64_t itemEntityId) → void
    耐久归零→发送 Event::ItemBroken→不可修复则RemoveItem
  GetEffectiveAttrBonuses(uint64_t characterEntityId) → AttrBonusSum
1.4.5 ItemLootSystem（掉落）
Text
职责：根据场景条件决定掉落物品和概率
核心方法：
  GenerateLoot(const LootContext& ctx) → std::vector<Entity*>
LootContext 结构：
  {
    sceneId: "car_3_luggage",          // 当前场景ID
    stageIndex: 2,                       // 探索阶段
    roundIndex: 1,                       // 当前轮次
    playerPER: 55,                       // 玩家当前感知值
    playerSTR: 62,                       // 玩家当前力量值
    playerWIL: 48,                       // 玩家当前意志值
    collectedClueIds: [1,3,5],          // 已收集线索ID列表
    chenHuiAlive: true,                 // 陈慧是否存活
    miGoDeceived: false,                // 是否已被米·戈欺骗
    shoggothTriggered: false,           // 是否已触发修格斯遭遇战
    shoggothRepelled: false,            // 是否成功驱退修格斯
  }
算法：
  1. 从LootTableRegistry查 sceneId+stageIndex 的所有条目
  2. 逐条检查 condition 是否满足（属性阈值/前置线索/事件状态）
  3. 满足条件时：guaranteed=true → 必定掉落；guaranteed=false → 按dropWeight加权随机
  4. 每轮最多掉落3件物品
  5. 调用ItemFactory创建Entity
  6. 发送 Event::LootGenerated
1.5 ItemSystemManager（单例）
Cpp
class ItemSystemManager {
public:
    static ItemSystemManager& Instance();
    void Init();          // 按依赖序初始化
    void Shutdown();      
    // 内部持有
    EntityManager       entityMgr;       // 实体容器
    ComponentPool       componentPools[ComponentType::COUNT];  // 6个Pool
    ItemFactory         factory;         // 依赖 entityMgr + componentPools
    InventorySystem     inventory;       // 依赖 entityMgr + componentPools
    ItemQuerySystem     query;           // 依赖 componentPools（建索引）
    ItemEquipSystem     equip;           // 依赖 entityMgr + componentPools
    ItemLootSystem      loot;            // 依赖 factory
    EventBus            eventBus;        // System间通信
    ItemTemplateRegistry templates;      // 策划配置数据
    LootTableRegistry   lootTables;      // 掉落表配置
};
