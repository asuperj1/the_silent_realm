# 物品格子组件全系统应用方案

> 日期：2026-08-29 ｜ 状态：方案定稿 + 核心接入完成
> 目标：把「物品格子」抽象为 **1 内核 + 3 组件**，应用到现有系统的全部适合场景，保证无 bug、无视觉错误，且一处改动全局生效。

---

## 一、组件架构

```
frontend/js/components/
├── ItemGrid.js            # 内核：物品卡片渲染 + 定位式/流式格子 + 拖拽(dragstart/drop) + 点击 + 空槽补齐
│                          #   · 不绑定 socket/业务，纯 DOM 可复用
│                          #   · itemCard(cardClass) 按类名映射内部结构：grid-item / forge-eq / ws-devour-eq
│                          #   · renderPositioned（定位式，grid.x/y+size 多尺寸）
│                          #   · renderFlow（流式，auto-fill + 空槽补齐铺满）
│                          #   · bindDrag / bindDrop / gridPosFromEvent / partitionFor
│                          #   · cardPost(card, it) 钩子：宿主挂金色浮窗/自定义交互
├── WarehouseGrid.js       # 组件1 仓库格子：仓库大格定位式 + 拖入(moveToWarehouse)/装备槽拖出(unequipToWarehouse)
├── InventoryGrid.js       # 组件2 背包格子：分区定位式 + 拖入类型校验(moveToInventory)/卸下(unequipItem)
│                          #   · renderEquipSlots：通用 6 部位装备槽（拖入装载/拖出卸下）
└── EquipMaterialGrid.js   # 组件3 装备/材料格子：filterPool(mode: equip|equip+material|all) + 流式渲染
                           #   · 覆盖锻造炉池 / 吞噬池 / 背包平铺兜底
```

**拖拽协议**（各场景 MIME 与载荷）：
| 场景 | MIME | 载荷 |
|---|---|---|
| 仓库 / 背包分区 / 装备槽 | `application/x-wh` | JSON `{ uid, from, slot }` |
| 锻造炉装备池 | `application/x-forge` | `uid` |
| 吞噬装备池 | `application/x-devour` | `uid` |
| 副本内背包（移动/快捷栏） | `text/plain` | `uid` 或 `__remove__`+uid |

## 四、视觉与交互保证（防 bug / 防视觉错误）

1. **卡片结构一致**：组件 `itemCard` 按 `cardClass` 输出与既有 CSS 完全一致的内部类名（`gicon/gname/gstack/gq`、`forge-eq-*`、`ws-devour-eq-*`），不新增破坏性结构。
2. **空槽类名对齐**：组件 `emptyCls` 必须显式传现有 CSS 类（`ws-devour-empty` / `forge-empty`），默认 `cardClass+'-empty'` 与现有样式不匹配。
3. **拖拽协议不变**：各场景 MIME/载荷保持原状，服务端 handler 与快捷栏/装备栏 drop 逻辑零改动。
4. **Tooltip 单一来源**：`attachItemTooltip` → `attachGoldTooltip` 会 `removeAttribute('title')`，配合 `cardPost` 不会出现原生 title + 金色浮窗双显示。
5. **点击不变**：`onClick` 钩子接回原 `itemMenu` / 三格逻辑 / 放炉逻辑，交互语义不变。
6. **容量 / 徽章计算保留**：`updateCap` / `renderInventory` 的容量、`_equipCache`、`_devourM/F` 等业务状态全部由调用方保留，组件只做纯渲染。
7. **幂等绑定**：`bindDrop` 用 `board._igDropBound` 防重复绑定；`renderFlow` 用 `board._igClickBound` 防重复委托，反复重渲染安全。

## 五、风险与规避

| 风险 | 规避 |
|---|---|
| 组件回归影响多处 | 每处接入后浏览器端到端验证 + `npm test` 24/24 回归 |
| 卡片结构变化破坏视觉 | `cardClass` 映射 + `noQbar` 选项，逐项对照旧截图 |
| 拖拽 MIME 不一致导致 drop 失效 | 各场景 MIME 固定，dragstart 数据用 `DragEvent` 模拟验证 |
| 双浮窗 / tooltip 错乱 | `attachGoldTooltip` 自动移除原生 title |
| 服务器缓存旧前端 | 前端静态改动 Ctrl+F5；服务端改动须重启 node |
